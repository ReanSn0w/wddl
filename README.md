# webdav

Утилита для загрузки файлов с WebDav на локальную машину

## Очередь загрузок

Незавершённые задачи хранятся в памяти процесса и после каждого добавления или
удаления атомарно сохраняются в читаемом версионированном JSON-файле. Путь
задаётся через `QUEUE_FILE` или `--queue-file` и по умолчанию равен
`./queue.json`.

Если очередь должна переживать пересоздание контейнера, размещайте файл на
постоянном volume. В Docker-образе используется `/data/queue.json` внутри уже
объявленного volume `/data`.

Один файл очереди предназначен только для одного экземпляра `wddl`. Не
редактируйте и не удаляйте его во время работы приложения. Пустой, повреждённый
или созданный более новой несовместимой версией файл не перезаписывается:
приложение завершит запуск и сообщит об ошибке.

`queue.json` можно удалить при остановленном контейнере. Очередь начнёт работу
пустой и восстановит удалённые задачи во время следующего сканирования WebDAV.
Уже скачанные корректные части находятся отдельно в `TEMP/<file-id>` и будут
использованы для продолжения загрузки, поскольку формат очереди не меняет ID
файла.

## Дополнительные локальные библиотеки

`wddl` может учитывать файлы, которые уже перенесены из каталога загрузок в
другие медиабиблиотеки. Укажите их повторяемым флагом `--existing-root` или
переменной `EXISTING_FILES_ROOTS`, разделяя пути запятыми. Пустые элементы и
пробелы вокруг путей игнорируются. Интервал полного обновления задаётся через
`EXISTING_FILES_SCAN_EVERY` или `--existing-files-scan-every`; значение по
умолчанию — `24h`.

При запуске все настроенные каталоги рекурсивно сканируются до подключения
движка загрузок. Индекс содержит только метаданные и полностью заменяется после
успешного повторного обхода. Если очередное сканирование завершилось ошибкой,
предыдущий снимок остаётся активным.

Совпадением считается только точная регистрозависимая пара «имя файла + размер
в байтах». Путь, время изменения и содержимое не сравниваются. Перед каждым
положительным ответом индекс повторно проверяет реальный файл через `stat`,
поэтому удалённая или изменённая после сканирования локальная копия не считается
совпадением.

Пример запуска с двумя библиотеками, примонтированными только для чтения:

```sh
docker run --name wddl \
  -e WEBDAV_SERVER=https://example.invalid/dav \
  -e WEBDAV_USER=user \
  -e WEBDAV_PASSWORD=password \
  -e INPUT=/Sync \
  -e OUTPUT=/data/download \
  -e TEMP=/data/tmp \
  -e QUEUE_FILE=/data/queue.json \
  -e EXISTING_FILES_ROOTS=/libraries/movies,/libraries/archive \
  -e EXISTING_FILES_SCAN_EVERY=24h \
  -v /volume1/wddl:/data \
  -v /volume1/video/movies:/libraries/movies:ro \
  -v /volume1/video/archive:/libraries/archive:ro \
  wddl
```

Без дополнительных корней сохраняется прежнее поведение: готовый файл ищется
только по ожидаемому пути внутри `OUTPUT`.

`CLEAR_REMOTE=true` и одноразовый режим `UTIL_CLEAR_REMOTE=true` физически
удаляют с WebDAV файлы, для которых найдена локальная копия. Перед каждым
удалением путь, имя и размер локального файла проверяются повторно. Оставляйте
оба режима выключенными, если удалённое хранилище должно оставаться неизменным.
